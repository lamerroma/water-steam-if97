Розглянуто наявні локальні зміни реакторного спринту; нові модулі продукту під час стабілізації не додавалися.

Виправлено відновлення виду діаграми та створення автономного ZIP на цьому ПК. Оновлено сценарії навігації в перевірках. Додано послідовний релізний запуск із журналами, SHA256, незалежною перевіркою ZIP і спільним workflow для CI та Pages.

## Перевірка виправлень

Окремий повтор діаграм, ізоліній, якості Canvas/SVG та гідравліки пройшов після виправлень. Перевірено reload, мову й одиниці, керування мишею/клавіатурою/сенсорними подіями, JSON, SVG/PNG/CSV/HTML, мобільну ширину й автономний file://.

Новий приймальний інструмент спочатку виявив помилку нормалізації шляху у власному сервері; її виправлено. Його перший прогін також виявив непрацездатне пакування ZIP (REL-009). Ці невдалі протоколи збережено в локальному `.release/`, вони не зараховані як успішне приймання.

Повний прогін початкової стабілізації **1.16.2 / 2ca29305bb83** завершився успішно: **24 приймальні перевірки**, включно з 667/667 unit-тестами, трьома числовими звірками та **13/13 браузерними сценаріями**. Повторна збірка й повторний ZIP мають тотожні SHA256; незалежний Python-читач підтвердив CRC, склад і точний вміст архіву.

[Машинний підсумок приймання](RELEASE_ACCEPTANCE.json) містить перевірки, середовище, метадані та SHA256 артефактів. Повні локальні журнали: `.release/2026-10-12T18-36-27-053Z/`. Середовище: Node.js 20.19.2, Python 3.13.5, Playwright 1.62.1, Chromium 151.0.7922.34.

Архів: `dist/water-steam-calculator.zip`, 5864916 байт. У ньому автономний калькулятор, інструкція запуску, швидкий старт українською, ліцензія, атрибуція та `BUILD_INFO.json`.

## Як відтворити

```sh
npm run verify:release
```

Потрібні Node.js ≥20, Python 3 і Playwright/Chromium. Для встановлених поза репозиторієм компонентів використовуйте `PLAYWRIGHT_MODULE_PATH`, `CHROMIUM_PATH`; для Python — `REACTOR_PYTHON`. Сервер створюється самим сценарієм. ZIP збирається стандартною бібліотекою Node.js, зовнішня утиліта не потрібна.

У `.release/<дата>/` записуються журнали, числові результати й `report.json`. Протокол позначає режим запуску (`full`, `core`, `browser`), всі виконані перевірки, версію/збірку та SHA256 готових файлів. Неуспішна перевірка повертає ненульовий код. Протокол програмного приймання не означає підтвердження всіх фізичних моделей.

## Що залишається до повного релізу

1. Виправлення фізичної нейтронної моделі після невдалого порівняння комірок IAEA ZR-6 (+11% у k); окремо — застосовність CHF, кипіння та неоднозначності методички. До підтвердження модуль залишається дослідним.
2. Походження результатів узгоджено у 1.16.5; захист збереження додано у 1.16.6. Обидва сценарії входять до повного приймання 1.16.7.
3. Перевірка на інших браузерах і реальному телефоні, повна перевірка клавіатури та навчальне випробування за інструкцією.
4. Виконання нового workflow на GitHub після доручення на пуш, перевірка опублікованого сайту й реального оновлення встановленої версії.

Стабілізацію розпочато та створено відтворюване програмне приймання. Весь план релізу цим аудитом не завершений.

Сувора команда `npm run verify:reactor:benchmark` повертає код 1. [Протокол та межі висновку](REACTOR_CELL_VALIDATION_UK.md).

Повної готовності нейтронної моделі не заявлено; публікацію цієї версії не виконано.
