# R02: релізний кандидат 1.40.0

Дата: **21.10.2026**. Поточний локальний build **20fd3cb17a71**.
Статус локального зрізу перед пушем: **усе покриття прийняте після повтору виправленого тестового драйвера; CI нового коміту ще не виконано; публікація не виконана**.
Остання підтверджена [публікація — 1.39.0](../RELEASE_STATUS_UK.md).
[R01: пам’ять і холодний запуск](../development-r01/MEMORY_ACCEPTANCE_UK.md)
прийняті окремо для настільного сценарію на попередньому build `0e0860132fb6`.

## Знайдено та виправлено

Перший повний прогін було зупинено після підтвердження помилки редактора циклу.
`ensureWaterModel` додає асинхронну підготовку перед першим запитом Worker.
У цей проміжок генератор перевіряв тільки `runner.busy`, тому редагування кінцевої
умови не скасовувало підготовку й пізніше вставлявся зайвий стан. Тепер перевіряється
і зайнятість форми, яка охоплює підготовку. Вибір іншого початкового стану також
скасовує задачу. Поведінковий браузерний тест відтворює обидві дії в тому самому
JS-завданні перед продовженням асинхронного коду.

Старі тести P06, навчального workflow і мобільного UI перевіряли готовність
синхронно після submit. Їхні очікування враховують Worker; числові допуски,
обов’язкові повідомлення помилок і заборона застарілих результатів збережені.
Окремо виправлено декодування `file:` URL у Windows/Unicode-шлях у CLI-аудиті P08.
Незалежний читач після виправлення перевірив 91 файл і 33 138 клітинок.
[Сирі таблиці й протокол фінального build](evidence/p08-final/README_UK.md) збережені з SHA-256.

[Початковий перерваний протокол](evidence/initial-interrupted-run/report.json)
зберігає відмови; він не є завершеним прийманням. Зміни чисельних моделей
під час цього виправлення не вносилися.

## Реальне оновлення PWA

Перевіряється перехід **1.39.0 / 0268d327cdad → 1.40.0**, той самий origin
і підкаталог `/water-steam-if97/`, через справжній Service Worker. Окремі профілі
Chromium/Firefox створюються тільки для тесту. Старі 12 core-файлів і 14 файлів
Python-пакета видобуто з опублікованого коміту
`a5d8a0759c4a0c10c803679b7818fb33af31332c`; кожний ресурс перевірено за старими
SHA-256 і розміром optional-пакета. [Маніфест походження](upgrade-evidence/baseline-source-manifest.json).

Сценарій зберігає назву проєкту, явні одиниці bar/°C, канонічну історію IF97,
англійську мову та підготовлений Python-пакет. Потім перевіряє HEOS при 1 MPa,
500 K, закриває браузер, відключає сервер/мережу, відновлює проєкт і повторює
HEOS та `ht.LMTD(100,60,30,40)` з кешу. Це локальна перевірка механізму оновлення,
а не свідчення вже виконаного deployment. Звіти й скриншоти містять точні build.

Відтворення: `node scripts/prepare-pwa-baseline.mjs <повний-SHA> <нова-папка>`;
потім `node scripts/check-pwa-upgrade-browser.cjs` з `PWA_BASELINE_ROOT`,
`BROWSER_NAME=chromium|firefox`, `PLAYWRIGHT_MODULE_PATH` і новою
`PWA_UPGRADE_EVIDENCE`. Git має містити старий коміт; завантаження еталона
мережею не потрібне. Тимчасові профілі збережені лише у `.release/`.

## Драйвер перевірки публікації

[`check-published-heos-browser.cjs`](../../scripts/check-published-heos-browser.cjs)
вимагає явних `PUBLISHED_URL` та `PUBLISHED_BUILD`. Його
[локальний Chromium-протокол](evidence/deployment-driver-local/chromium/report.json)
та [Firefox-протокол](evidence/deployment-driver-local/firefox/report.json)
перевіряють чотири CSV-виводи P–T/P–h онлайн/офлайн, вісім властивостей
за незалежною фікстурою, JSON-проєкт, точний build і недоступність мережі
після закриття профілю. **URL цих протоколів локальний; живий сайт ними не перевірено.**

У довгому тестовому шляху профілю Chromium двічі не завершив підготовку кешу;
[збережений діагностичний протокол](evidence/deployment-driver-local/diagnostic-long-profile/report.json).
Із коротким новим профілем у системній тимчасовій папці сценарій успішний.
Обмеження довжини шляху — робоча гіпотеза, точну причину не встановлено.
Короткі незалежні профілі використовуються також чинними HEOS-драйверами.

## Решта приймання

Повторний повний `verify-release.mjs` завершено після виправлення продукту.
[Машиночитне приймання з SHA-256](acceptance.json) і
[сирий протокол](evidence/full-local/report.json) збережені.

| Перевірка | Спостережений результат |
| --- | --- |
| Повний локальний прогін | 105/106 одразу; первинний статус `failed` збережений |
| Повтор єдиного виправленого тесту звіту | Успішний на build 20fd3cb17a71; усі п’ять розділів, HTML/PDF/JSON та офлайн |
| Модульні тести Node 22 / Node 24 | По 1806/1806, без пропусків |
| Повний незалежний inverse-аудит | 4657/4657 |
| HEOS, 595 запитів | 582 matched, 6 ambiguous, 7 conditioned, 0 failed |
| Незалежні аудити P02 / P05 / P06 / P07 | 745/745; 435/435; 97/97; 184/184 |
| P08, незалежні читачі | 91 файл, 33 138 клітинок; додатково по 60 браузерних експортів і 160 перевірок у Chromium/Firefox |
| Реальне оновлення 1.39.0 → 1.40.0 | Пройдено в обох браузерах, включно з підготовленим Python-пакетом і офлайн-перезапуском |
| Збірка, ZIP, цілісність | Успішні, повторні SHA-256 і ZIP збігаються |

Під час повного прогону старий тест `browser-study` додавав турбіну до звіту
до завершення Worker: виходило 4 замість 5 розділів. Додано очікування готового
CSV; усі початкові вимоги збережені. [Повтор на тому самому build](evidence/study-corrected-chromium-final.log)
успішний. Це приймання всього покриття з окремим повтором, **не оголошення
первинного повного прогону безперервно зеленим**. Чисельний код і build не змінювалися.

Середовище: Windows, Node 22.23.3/24.18.1, Python 3.12.10, Playwright 1.62.1,
Chromium 151.0.7922.34 / Firefox 153.0. CI окремо використовує Linux, Node 22,
Python 3.12 і pinned Playwright 1.64.1. Виміряний новий блок HEOS у двох браузерах
зайняв близько 17 хвилин на цьому Windows-ПК; бюджет повного CI збільшено до
45 хвилин, очікування Pages узгоджено до 50/55 хвилин. Жодного assertion не вилучено;
Pages далі вимагає успішний CI **того самого коміту**.

Цей датований документ фіксує локальний стан перед пушем. Поточний CI слід
перевіряти в [Actions](https://github.com/lamerroma/water-steam-if97/actions).
До підтвердження CI/Pages та живої збірки R02 залишається відкритим.

Наявні незакомічені зміни збережено у R00 і перевірених delta-копіях у `.release/`;
результати відновлення й SHA наведено в локальних manifest. Для відновлення
публікації слід створити окремий revert-коміт релізу і пройти ті самі CI/Pages;
локальні робочі файли не скидати. Перед відкотом зберегти JSON-проєкти: 1.39.0
не має моделі HEOS::Water, тому їхні нові розрахунки потребують 1.40.0 або
окремої явної конверсії. Сховище браузера не очищати. Коміт релізу визначається
тільки після його створення.

Це програмне приймання. Числових результатів Steam97Web досі 0, паритет P03/P04
не підтверджений. Нейтронна комірка залишається `physical-screening-failed`;
фізичні телефони/Safari та повне числове приймання ht/fluids — окремі роботи.

Після цього локального зрізу виконано [перший GitHub CI та адресне виправлення драйвера](CI_FOLLOWUP_UK.md).
