# R01 — турбіна та дроселювання у Worker

Кандидат цього етапу **1.39.0 / 73fbb518e323**, 21.10.2026; не опублікований.
Наступний кандидат описано в [інженерних формах і діаграмах у Worker](AUXILIARY_WORKER_UK.md).
Це продовження [попереднього звіту R01](REPORT_UK.md), а не завершення всього
R01 або повне релізне приймання. [Точні дані й докази](steam-process-acceptance.json).

## Підтверджена проблема й зміна

Окремі форми турбіни та дроселювання виконували ядро властивостей синхронно.
Перший запит Water у HEOS блокував головний потік. Для кожного інструмента
брали новий браузерний контекст; до вимірювання не виконували загальний
HEOS-розрахунок. Звичайний попередній розрахунок приховав би цю холодну паузу.

Тепер усі три режими турбіни — потужність, витрата, ККД — та всі три режими
дроселювання передають канонічні входи через `workflows / steam-process`.
Маршрутизатор використовує окремий HEOS Worker; IF97 та IAPWS-95 використовують
наявний звичайний Worker. Формули, моделі, нулі h/s та фізичні допуски не змінені.
Температура насиченого конденсату береться з розрахованого входу Worker,
без додаткового запиту властивостей у головному потоці.

Кнопка скасування завершує Worker. Редагування й навігація також скасовують
незавершений запит; перевірка ревізії, моделі та живої форми не дозволяє
застарілому результату потрапити у проєкт. Наступний розрахунок створює
новий Worker. Зміна входів зберігає ознаку нерозрахованої форми.

## Числові докази

Незалежний генератор
[`generate-steam-process-reference.py`](../../scripts/reference/generate-steam-process-reference.py)
використовує Python `iapws==1.5.5` та не імпортує продукт. Шість контрольних
випадків: p₁ = 3 MPa, p₂ = 0,1 MPa; для турбіни T₁ = 673,15 K,
для ненасиченого конденсату T₁ = 473,15 K. Потужність для обернених режимів
600 kW; задані витрата 1 kg/s та ККД 0,85 використовуються відповідно до режиму.

У цих випадках виходи двофазні. Еталон визначає їх за насиченими кінцями й
правилом важеля h/s; загальний Python inverse solver не використовується.
Допуски порівняння: p — 10⁻⁸ MPa, T — 3×10⁻⁶ K, h — 10⁻⁵ kJ/kg,
s — 3×10⁻⁸ kJ/(kg K), питомі/потокові метрики — 3×10⁻⁶ у канонічних одиницях.
Різниця незалежного Python-розв’язку насичення біля 3 MPa становить приблизно
3×10⁻⁶ kJ/kg за h; це враховано в допуску еталона, не в алгоритмі продукту.

Нові модульні перевірки охоплюють усі шість режимів для трьох моделей,
маршрутизацію, серіалізацію, масовий та енергетичний баланси й відмови
неприпустимих входів. Незалежні значення IAPWS-95 порівнюються з IAPWS-95 та
HEOS; для IF97 перевіряються його власні баланси, без вимоги тотожності моделей.
Браузерні CSV також порівнюються з незалежними контрольними значеннями.

## Браузери, офлайн та реакція інтерфейсу

Вимірювання використовує незмінені зібрані assets, headless desktop Chromium
і Firefox, loopback та таймер 20 ms. Пауза — найбільший проміжок цього таймера,
а не загальний час розрахунку. Дані «до/після» і точні часи збережені в JSON.
Це одиничні вимірювання на одному ПК, не статистична оцінка й не гарантія
для мобільних пристроїв. Бюджет 1000 ms є запропонованим контрольним порогом.

Окремий сценарій перевіряє кеш PWA, відключає мережу й перезавантажує сторінку
до вибору HEOS. Усі наступні Worker-розрахунки, CSV, повтори після скасування
та відновлення проєкту виконуються офлайн. Перевіряються також bar/F/kg/h,
відмова при p₂ ≥ p₁, повтор після помилки, англійська мова та ширина 390 px.
390 px не замінює перевірку фізичного телефона.

Повний модульний набір: **1799/1799** у Node 22.23.3 та Node 24.18.1,
без пропусків. Chromium 151.0.7922.34 і Firefox 153.0: по шість числових
випадків онлайн і офлайн та по 14 додаткових офлайн-перевірок керування формами.
У кожному браузері всі рядки шести CSV до/після/офлайн тотожні після вилучення
чотирьох колонок метаданих експорту.

| Перший розрахунок: максимальна пауза | До, f16d46d30b5e | Після, 73fbb518e323 |
| --- | ---: | ---: |
| Chromium, турбіна | 2408.4 ms | 34.6 ms |
| Chromium, дроселювання | 2260.6 ms | 25.1 ms |
| Firefox, турбіна | 13814.0 ms | 32.0 ms |
| Firefox, дроселювання | 13796.0 ms | 35.0 ms |

Для відтворення: `node --test tests/steam-process-worker.test.mjs` та
`node scripts/check-steam-process-worker-browser.cjs`.
Змінні: `BROWSER_NAME=chromium|firefox`, `PLAYWRIGHT_MODULE_PATH` — локальний
Playwright; `STEAM_PROCESS_OFFLINE=1` — офлайн-сценарій;
`STEAM_PROCESS_EVIDENCE` — каталог доказів. `--measure-only` залишає числові
CSV-перевірки й вимірювання, пропускаючи додаткові сценарії керування формою.

## Що залишилося

R01 відкритий: інженерні форми, побудова/уточнення діаграм, приймання холодного
запуску та пам’яті. Холодна підготовка HEOS у Worker все ще потребує секунд;
цей крок прибирає блокування інтерфейсу, а не всю затримку отримання результату.
Новий повний релізний прогін, перевірка оновлення PWA з опублікованої версії,
CI/Pages та публікація належать R02. Числових результатів Steam97Web не додано;
цей звіт не доводить паритет оригіналу або фізичну валідацію нейтронної моделі.
