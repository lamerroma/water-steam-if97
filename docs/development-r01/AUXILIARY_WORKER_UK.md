# R01 — інженерні форми та діаграми у Worker

Локальний кандидат **1.39.0 / d6ed1ea111e3**, 21.10.2026, без публікації.
Продовження [турбіни/flash у Worker](STEAM_PROCESS_WORKER_UK.md).
[Точні дані, контрольні суми та докази](auxiliary-acceptance.json).
R01 залишається відкритим для приймання пам’яті й холодного запуску;
цей звіт фіксує окрему завершену інтеграцію.

## Зміни

Насос, компресор та баланс двопотокового теплообмінника передають канонічні
аргументи через `workflows / engineering`. Діаграми використовують
`diagram-base`, `diagram-isotherm` та `diagram-refine`. Початкова сітка,
підписи термодинамічних областей, ізотерми та нові модельні проби адаптивного
уточнення обчислюються у Worker. Canvas/SVG, геометрія відображення та
керування залишаються в інтерфейсі. Числові ядра та фізичні допуски не змінені.

Інженерна форма та діаграма використовують один спільний послідовний runner:
завершені запити зберігають прогрітий Worker; скасування активного запиту
завершує його. HEOS має власний WASM Worker, IF97/IAPWS-95 — звичайний.
Це не твердження, що вся програма має лише один Worker.

Для інженерних форм додано кнопку скасування, перевірку ревізії входів,
моделі та живої форми перед збереженням результату. Для початкової сітки
діаграми з’явився стан завантаження зі скасуванням; вихід із розділу завершує
незакінчену побудову. Зміна масштабу відкидає попереднє уточнення;
при побудові ізотерм уточнення не конкурує за той самий runner.

Команди показу процесу на діаграмі передають запит підбору масштабу разом
із відкриттям. Це зберігає переходи з турбіни, інженерних форм, навчальних
прикладів і таблиці насичення, коли Canvas ще не створено.

## Незалежні числові контроли

[`generate-engineering-reference.py`](../../scripts/reference/generate-engineering-reference.py)
використовує Python `iapws==1.5.5` та SciPy `brentq`, без імпорту продукту.
Обернені задачі розв’язуються за температурою у заданих однофазних інтервалах;
залишок h/s перевіряється окремо.

| Випадок | Канонічні входи |
| --- | --- |
| Насос | p₁ = 0,1 MPa; T₁ = 293,15 K; p₂ = 10 MPa; η = 0,8; ṁ = 2 kg/s |
| Компресор | p₁ = 0,1 MPa; T₁ = 423,15 K; p₂ = 1 MPa; η = 0,8; ṁ = 2 kg/s |
| Теплообмінник | гарячий: 1 → 1 MPa, 423,15 K, 2 kg/s; холодний: 0,1 → 0,1 MPa, 293,15 K, 3 kg/s; Q̇ = 200 kW |

Для IAPWS-95 та HEOS перевіряються p/T/ρ/h/s усіх входів, виходів та ідеальних
станів і метрики процесу. Абсолютний допуск — 2×10⁻⁶ у канонічних одиницях,
для s — 2×10⁻⁸ kJ/(kg K). IF97 перевіряється за власними балансами, без
нав’язування тотожності з IAPWS-95. Додано незалежні контроли трьох модельних
підписів діаграми, перевірку ізотерми з обома кінцями насичення, пропусків,
прихованих ізобар, збереження моделі й бюджету уточнення.

Це незалежна програмна реалізація тієї самої EOS, не експериментальна перевірка
і не числовий еталон Steam97Web. Нових чисел оригіналу не отримано.

## Спостережені браузерні результати

Дані «до»: build `73fbb518e323`; «після»: `ba491efebede`.
Після цих вимірювань у кінцевому `d6ed1ea111e3` виправлено статус завершення,
помилки й редагування інженерної форми. Повторне офлайн-приймання та модульні
тести стосуються кінцевого кандидата; числові ядра й Worker-методи між цими
двома новими збірками не змінювалися. Кожен інструмент
починається у новому контексті без попереднього запиту властивостей Water.
Таймер 20 ms спостерігає головний потік. У JSON окремо збережено загальний
час до результату; він не дорівнює паузі інтерфейсу.

У Chromium і Firefox числові рядки всіх трьох CSV до/після тотожні після
вилучення чотирьох колонок метаданих експорту. Повні масиви даних діаграми
та статистика уточнення також тотожні у трьох знімках: початковий вигляд,
ізотерми, масштабований вид. Кількість нових модельних проб у цих знімках —
540, 1521 і 3621 відповідно; бюджет 6000 не перевищено, `limited=false`.

Повний модульний набір кінцевого кандидата: **1806/1806** у Node 22.23.3 та
Node 24.18.1, без пропусків. Остаточні офлайн-сценарії Chromium 151.0.7922.34
та Firefox 153.0 пройшли по 22 додаткові перевірки; статус завершення
інженерного розрахунку перевіряється явно.

Вимірювання виконані headless на одному настільному ПК; паралельно могли
працювати інші перевірки. Це одиничні спостереження, не статистична оцінка
швидкодії або гарантія для інших пристроїв. Запропонований поріг паузи — 1000 ms.
Підготовка HEOS у Worker все ще займає секунди; прискорення всієї холодної
задачі цим звітом не заявляється.

Окремі браузерні сценарії перевіряють PWA-кеш, відключають мережу й
перезавантажують сторінку до вибору HEOS. Покриті скасування, редагування,
навігація, повтор, відновлення проєкту, помилкові входи, англійська мова та
390 px. Для діаграм — три системи координат, зміни масштабу, ізотерми,
відновлення та вихід під час холодної побудови без створення застарілого Chart.
Фізичні телефони й Safari цими сценаріями не перевірені.

Додаткові чинні сценарії діаграм перевіряють SVG/Canvas-геометрію, критичну
ізобару IF97, PNG/SVG/CSV/HTML, перенесення процесів і насичення, жести,
зменшений рух, 4× CPU throttling та офлайн. Очікування тестів тепер враховують
асинхронне створення Canvas; числові й геометричні вимоги не послаблені.

## Відтворення та решта роботи

Python-залежності зафіксовані у
[`requirements-water-heos.txt`](../../scripts/reference/requirements-water-heos.txt).

`node --test tests/auxiliary-worker.test.mjs`;
`node scripts/check-auxiliary-worker-browser.cjs`.
Змінні: `BROWSER_NAME=chromium|firefox`, `PLAYWRIGHT_MODULE_PATH`,
`AUXILIARY_OFFLINE=1`, `AUXILIARY_EVIDENCE`.
`--baseline` вимірює попередню збірку без вимоги наявності нових Worker-методів;
`AUXILIARY_ROOT` задає її статичний каталог.

Далі у R01: оновлені вимірювання пам’яті, довготривалих повторів і холодного
запуску поточної архітектури та критерії їх приймання. Інші наукові панелі
з прямими викликами CoolProp залишаються окремою роботою. Повний релізний
прогін, оновлення встановленої PWA, читання експортів незалежними програмами
та CI/Pages належать R02. Поточні локальні перевірки не означають публікації,
паритету Steam97Web або фізичної валідації нейтронної моделі.
