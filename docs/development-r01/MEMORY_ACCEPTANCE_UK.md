# R01: приймання пам’яті та холодного запуску

Дата: **21.10.2026**. Локальний кандидат **1.40.0 / 0e0860132fb6**, не опублікований.
R01 завершено в межах виміряного настільного сценарію. Повне релізне приймання
та публікація належать R02. [Точні дані та SHA-256](memory-acceptance.json).
Попередні [виправлення](REPORT_UK.md), [турбіна/flash](STEAM_PROCESS_WORKER_UK.md)
та [інженерні форми/діаграми](AUXILIARY_WORKER_UK.md) зберігають свої історичні build.

## Спостережені результати

Windows, Ryzen 7 5700G, Node 24.18.1; headless Chromium 151.0.7922.34 та Firefox
153.0. Реальні форми програми, 15 переходів між діаграмами зі зміною масштабу,
10 скасувань із повторним розрахунком, 11 усталених знімків кожного браузера.
Результат насоса після кожного відновлення звірено з незалежною фікстурою IAPWS-95.
Основна форма перевіряє h при 1 MPa, 500 K. Джерела й CSV включені до архіву доказів.

Усі доступні критерії виконані. Невиміряні показники Firefox мають `null`, а не
успішний результат. Місткість WASM не дорівнює живій алокації, private commit
не дорівнює фізичній RAM; CDP-купа основної сторінки не включає JS-купи Workers.
Дискретні знімки не гарантують захоплення піків. Скасування виміряне як тривалість
UI-обробника; правильність подальшого результату перевіряється окремо.

Холодний запуск означає нову сторінку/рушій з локальними HTTP-ресурсами, а не
порожній кеш диска чи повільну мережу. Підготовка Worker у Firefox все ще займає
секунди; пауза інтерфейсу 220 ms не є часом усієї задачі. Ці запропоновані межі
прийнято для цього настільного сценарію; фізичні телефони та Safari належать R13.
Підтримуваний CI runtime — Node 22, додаткові модульні перевірки — Node 24.

## Виправлення методики

Перший драйвер утримував віддалені ElementHandle після `waitForSelector` Canvas.
Старі Canvas та їхні замикання залишалися доступними тесту: після 15 переходів
JS-купа сягала близько 54 MB. Заміна очікування на `Locator.waitFor`, яке не
повертає ElementHandle, усунула це зростання без зміни чисельного коду програми.
Повний повтор із 15 переходами та 10 скасуваннями дав таблицю вище.

[Перший Chromium-протокол](memory-evidence/driver-diagnostic/ui-memory-chromium.json)
зберігає невиконаний критерій. [Старий Firefox-прогін](memory-evidence/driver-diagnostic/ui-memory-firefox.json)
було свідомо перервано для виправлення драйвера; це не зависання продукту.
Старі дані не зараховані як успішне приймання.

## Відтворення

Драйвер: [`benchmark-heos-ui-memory.cjs`](../../scripts/benchmark-heos-ui-memory.cjs).
Після `npm run build` виконати `node scripts/benchmark-heos-ui-memory.cjs`.
Змінні: `PLAYWRIGHT_MODULE_PATH`, `BROWSER_NAME=chromium|firefox`,
`UI_MEMORY_CYCLES=10`, `UI_MEMORY_VIEWS=15`. Вихідний JSON можна задати аргументом.
Потрібні Playwright-браузери; на Windows Chrome-драйвер використовує PowerShell
для private commit. Архів: [Chromium](memory-evidence/ui-memory-chromium.json),
[Firefox](memory-evidence/ui-memory-firefox.json), поруч CSV, журнали й скриншоти.
Спостерігач лише читає іменований WASM memory export, математичні відповіді не підміняє.

Прямий паритет Steam97Web залишається непідтвердженим: 0 числових результатів
оригіналу. Фізична перевірка нейтронної комірки залишається невдалою.
