# Якість діаграм — 1.5.0

## Деталізація при наближенні

T–s, h–s і P–h залишаються на Chart.js. Після зміни масштабу, розміру графіка або видимих допоміжних кривих програма уточнює видимі ділянки купола, ізобар, ізотерм і ліній сухості. Додаткові точки обчислюються обраною моделлю IF97 або IAPWS-95. Сплайни не застосовуються; пропуски моделі розривають лінію.

Алгоритм перевіряє відхилення обчисленої середньої точки від відрізка у координатах екрана. Орієнтир — 0,65 пікселя. Це критерій деталізації зображення, а не гарантія фізичної точності чи глобальна оцінка похибки кривої. Початкова сітка зберігається. Ділянки, що вже достатньо прямі, не отримують зайвих точок. Для P–h використовується логарифм абсолютного тиску.

Робота починається через 180 мс після зміни вигляду. Під час жесту відразу перемальовуються наявні точки. Між групами обчислень керування повертається браузеру; новий масштаб скасовує застаріле завдання. Є межі глибини поділу й числа оцінок: до 900 на окремий прохід і до 3600 на вигляд, плюс початкові зразки визначених процесів. Шість останніх виглядів кешуються в поточній вкладці діаграми. За досягнення межі з’являється пояснення; необмежену деталізацію не обіцяємо.

Кнопки SVG, PNG, HTML та звіту в меню «Файл» недоступні під час уточнення, щоб не вивантажити незавершений вигляд. CSV експортує користувацькі стани й залишається доступним. Додаткові точки не потрапляють у журнал або JSON; після відкриття проєкту криві уточнюються знову.

## Фізичний зміст процесів

- Фактичний вхід і вихід турбіни/компресора з’єднано зеленою штриховою лінією. ККД визначає кінцевий стан, але не задає траєкторію між станами.
- Пунктирна ізоентропа обчислюється як s = const за проміжними абсолютними тисками й уточнюється для масштабу.
- Дроселювання показує обчислені рівноважні стани h = const. На P–h це вертикальна лінія; на інших діаграмах її форма визначається властивостями води. Це термодинамічна модель, а не просторовий шлях усередині дроселя.
- Лінії теплообмінника з’єднують кінцеві стани гарячого й холодного потоків і мають штриховий стиль.

Коротке пояснення видно під графіком без відкриття налаштувань. Воно також включене до опису SVG та HTML-звіту. Українська й англійська мови підтримуються.

## Узгодженість експорту

SVG використовує поточні дані Chart.js, положення обчислених точок, межі області побудови, фактичні поділки шкал і їхні локалізовані мітки. Кольори, товщина, штрихи, радіуси вибраних точок та порядок малювання також беруться з графіка. Положення підписів і геометрія стрілок спільні для Canvas і SVG. HTML-звіт використовує цей самий SVG. PNG зберігає Canvas у його поточному розмірі й щільності пікселів.

Перед експортом анімація завершується. Тимчасове перехрестя та спливаюча підказка не включаються. SVG залишається векторним; браузерні відмінності згладжування й шрифтів можливі.

## Перевірки

```bash
npm run build
npm test
npm run serve
# У другому терміналі з Playwright і Chromium:
npm run test:diagrams
npm run test:diagram-guides
npm run test:diagram-quality
```

Підтримуються `PLAYWRIGHT_MODULE_PATH`, `CHROMIUM_PATH`, `DIAGRAM_URL`. Нові перевірки охоплюють реальні обчислення середніх точок, відсутність сплайнів, збереження розривів, межу роботи й скасування, рівноважні суміші, незмінність s/h у визначених процесах, деталізацію критичної ізобари при наближенні, відповідність SVG поділкам/координатам Canvas, одиниці, мови, IAPWS-95 та автономну роботу. Мобільна браузерна перевірка використовує ширину 390 px та уповільнення CPU у 4 рази; це симуляція, а не вимірювання на фізичному телефоні.
