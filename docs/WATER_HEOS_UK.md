# Вода через CoolProp HEOS — пілот

Цей документ фіксує початковий етап M1 (8 режимів, адаптер 1.0.0).
Поточний адаптер 1.1.0 має [20 пар і числову інтеграцію циклів](WATER_HEOS_M2_UK.md).
Наведені нижче обмеження восьми режимів та докази build 28cfe47d42c9 є
історичним прийманням M1, а не повним описом поточного робочого коду.

У розділі «Бібліотеки CoolProp / ht / fluids» додано окрему форму води.
Вона викликає зафіксований CoolProp 8.0.0, HEOS::Water (IAPWS-95), у
Calculation Worker. Основна обрана формуляція, цикли та проєкти не змінюються.
Новий модуль ще не опубліковано; [план наступних етапів](OPEN_LIBRARY_MODULES_PLAN_UK.md).

## Входи та виходи

| Режим | Входи форми |
| --- | --- |
| PT | Абсолютний P, MPa; T, K |
| PH / PS / PU | Абсолютний P, MPa; h/u, kJ/kg або s, kJ/(kg K) |
| SATP / SATT | Абсолютний P, MPa або T, K |
| PX / TX | P, MPa або T, K; масова сухість x від 0 до 1 |

Форма має явні фіксовані одиниці. Параметри одиниць основного калькулятора
на неї не поширюються. Протокол `water-heos / calculate`, версія адаптера
1.0.0, підтримує також штатне перетворення явно переданих одиниць.

Показано p, T, rho, v, h, s, u, A, G, cp, cv, звук, Z, cp/cv, ізентропний
показник, транспорт і похідні. Одиниці виходів включено до `reply.quantities`.
Властивості недоступної області позначаються «—» і null у JSON. Для суміші
0 < x < 1 теплоємності, звук, транспорт і похідні не обчислюються; окремі
рідка й парова фази мають власні доступні значення. Змішування v/h/s/u
виконується за масовою сухістю.

Тиск 0 < P ≤ 1000 MPa, T ≤ 1273 K; нижня межа — реалізована крива плавлення
IAPWS R14-08, глобальний мінімум 251.165 K. Лід і метастабільні стани не
допускаються. Фактична збіжність залежить від стану: прямокутні межі не є
гарантією кожного оберненого виклику. Насичення: 273.16 ≤ T < 647.096 K;
точна критична точка виключена. μ/λ додатково обмежені R12-08/R15-11
через чинний water-validity.js; діелектрична проникність — R8-97.

P–T у смузі max(1e-12 MPa, 1e-6 від тиску насичення) повертає обидві фази
без довільного вибору x. Це відповідає обмеженню високорівневого PropsSI
поблизу співіснування. Температура або тиск насичення в результаті є
розрахованими для кривої, а не примусово скопійованими входами.

При PH/PS/PU можливий вихід нативної температури на відстань до 2e-7 K
за нижній рідинний або верхній замкнений край. Адаптер повторно обчислює
стан на допустимому краї й перевіряє залишок заданого h/s/u. Це усунення
числового округлення; для прямого PT вхід поза областю не виправляється.

h/s використовують стандартну систему відліку IAPWS-95 у CoolProp,
без зміни reference state. Це не система газових NASA7/BSW2003.

## Worker, експорт і офлайн

WASM ініціалізується лише при першому виклику. Скасування завершує Worker;
після нього наступний виклик створює новий. Зміна входів або вихід із розділу
скасовує поточний запит. При зміні входів старий експорт стає недоступним.

JSON містить точний payload, модель, версію адаптера, upstream-версію,
ревізію реалізації, одиниці, усі доступні числа, попередження й межі.
Екран показує до 12 значущих цифр; це формат, а не гарантія фізичної точності.
JSON зберігає повні Number-значення. Входи цієї пілотної форми поки не
включені до загального JSON-проєкту; для їх збереження використовуйте експорт.

Додатковий Python-пакет не потрібен. CoolProp WASM уже входить у базову PWA.
Сторінка та Worker використовують один ключ WASM за SHA-256 вмісту,
перевірений під час підготовки PWA. Пам'ять WASM у Worker окрема від сторінки.

## Перевірка

```sh
node --test tests/water-heos.test.mjs
node scripts/check-water-heos-browser.cjs
```

Другу команду повторити з BROWSER_NAME=firefox. Playwright доступний через
звичайний node_modules або PLAYWRIGHT_MODULE_PATH. Скрипт сам запускає
сервер на вільному порту з підшляхом /water-steam-if97/.

- 21 незалежний контрольний стан Python iapws 1.5.5: p/T/rho/h/s/cp/cv/w;
  PH/PS перевіряються з незалежними h/s. PU додатково перевіряє обернення
  власного прямого результату, отже не є незалежним контролем u.
- Шість станів аудиту: окрема [фікстура](../tests/fixtures/water-heos-regressions.json),
  включно з нижньою межею рідини. P–T/P–h/P–s перевіряються в Node і браузерах.
- Транспорт зіставляється з наявною нативною фікстурою CoolProp: це контроль
  інтеграції, а не незалежна експериментальна валідація.
- Окремо перевіряються одиниці похідних, термодинамічні тотожності, усі
  вісім режимів, null для двофазних виходів, недопустимі стани й модель.
- Браузерний сценарій перевіряє скасування холодного старту, чутливість UI,
  JSON, мову, ширину 390 px; потім закриває профіль, вимикає сервер і мережу,
  запускає профіль заново та обчислює в новому Worker з базового кешу.

Локальні точні відповіді й скриншоти створюються в `.release/water-heos/`.
Цей робочий каталог перезаписується повторними сценаріями; його поточний
вміст уже належить M2. Історичні числа M1 зафіксовані в наведеному нижче
підсумку, а актуальне приймання має окремий архів за ідентифікатором збірки.
Успішні перевірки цього обмеженого набору не доводять покриття решти 12 пар,
усіх фазових меж чи відповідності Steam97Web.

Локальне приймання 20.10.2026, build 28cfe47d42c9:

- Node 22.23.3: 1752/1752 модульних тестів; 19/19 перевірок core, включно
  з відтворюваною збіркою, пакетом і перевіркою його вмісту.
- Chromium 151 і Firefox 153: по 28 експортованих результатів Water HEOS,
  1165 звірок чисел/одиниць відображення та холодний офлайн-запуск.
- Наявні ht/fluids: по 10 груп браузерних регресій в обох браузерах.
- Node 24.18.1: 1751/1752; зберігається раніше підтверджена відмова густини
  старого IAPWS-95 у dry-saturated-inlet циклі Ренкіна. Пілот не виправляє
  чинні workflows. Повний браузерний release-набір цього етапу не запускався.
