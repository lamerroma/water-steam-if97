# Навчальний звіт і двоконтурна АЕС — 1.9.0

## Підготовка навчальної роботи

На вкладці виконайте розрахунок і натисніть «Додати до звіту» на панелі інструментів. Підтримано загальні властивості/насичення води й пари, турбіну, флеш, дроселювання, насос/компресор, двопотоковий теплообмінник, витрати/гідравліку та схему АЕС. На діаграмах кнопка додає PNG поточного масштабу після завершення побудови. Інші розділи поки не мають розрахункових блоків звіту.

У «22. Навчальний звіт» задайте автора, назву роботи, умову, назви блоків і пояснення. Переставляйте блоки кнопками «Вище»/«Нижче», видаляйте зайві. «Переглянути звіт» відкриває попередній перегляд; «Друк / PDF» викликає діалог браузера. PDF створюється вибором «Зберегти як PDF», а не окремим серверним конвертером. «Експорт навчального звіту HTML» зберігає автономний документ A4 з вихідними даними, результатами, формулами й припущеннями.

Назва документа береться з поля «Назва проєкту» в меню «Файл». Мова звіту відповідає вибраній мові інтерфейсу. Текст автора, назви й пояснення зберігаються дослівно. Входи фіксуються в канонічних одиницях: абсолютний MPa, K, kJ/kg, kJ/(kg K), частки; у схемі АЕС — також °C та MW. Зміна загальних одиниць не змінює ці дані.

Числові блоки перераховуються при імпорті/експорті з зафіксованих входів та моделі; імпортовані результати не приймаються за істину. Гідравліка фіксує отримані ρ і μ як входи та назву джерела властивостей; початковий стан джерела не відновлюється. Діаграма — знімок, вона не перемальовується при подальшому редагуванні станів.

Склад звіту автоматично зберігається й переноситься в JSON-проєкті через необов’язкове поле `study`. Старі проєкти відкриваються з порожнім звітом. Максимум 20 блоків, 1 МБ для звіту, 300 тисяч символів на PNG, 5000 px на сторону зображення; загальний проєкт — до 2 МБ. При перевищенні ліміту додавання відхиляється з повідомленням. HTML екранує користувацькі тексти, не містить скриптів і відкривається без мережі.

## Схема двоконтурної АЕС

Вкладка «21. Навчальна схема двоконтурної АЕС» зв’язує первинний контур із простим вторинним циклом через парогенератор. Вода контурів не змішується.

| Стан | Значення |
|---|---|
| P1 | Вхід реактора, стиснена вода |
| P2 | Вихід реактора, стиснена вода |
| S1 | Насичений рідкий конденсат |
| S2 | Після живильного насоса |
| S3 | Суха насичена пара з парогенератора |
| S4 | Після турбіни |

«Навчальний приклад ARIS» завантажує контрольний набір. «Стани на T–s»/«Стани на h–s» додають шість точок у журнал і відкривають графік; первинний і вторинний контури автоматично не з’єднуються однією лінією. Повторне натискання додає ще один набір станів. Обидві моделі IF97 та IAPWS-95 підтримані. Вхідні параметри й останній розрахунок відновлюються з проєкту.

### Джерело та навчальні припущення

Первинне джерело п’яти параметрів: [IAEA ARIS, Main Characteristics of Advanced Reactors](https://aris.iaea.org/Characteristics/), рядок VVER-1000 (V-466B), доступ 2026-10-11. Це підстава для вихідних даних навчального прикладу, а не підтвердження всіх результатів чи моделі установки.

| Параметр | Значення | Походження |
|---|---|---|
| Теплова потужність реактора | 3000 MW | IAEA ARIS |
| Тиск першого контуру | 15.7 MPa abs | IAEA ARIS |
| Вхід / вихід реактора | 291 / 321 °C | IAEA ARIS |
| Тиск пари | 6.27 MPa abs | IAEA ARIS |
| Тиск конденсатора | 0.005 MPa abs | Навчальне припущення |
| Ізоентропний ККД турбіни | 0.85 | Навчальне припущення |
| Ізоентропний ККД живильного насоса | 0.8 | Навчальне припущення |

Чиста вода в першому контурі має залишатися однофазною стисненою рідиною. Умови задаються при сталому тиску; первинний циркуляційний насос ідеальний, його робота дорівнює нулю. Прийнято консервативну умову T(P1) > T(S3), щоб уникнути перетину температур у спрощеному парогенераторі.

У вторинному циклі відсутні сепарація вологи, проміжний перегрів, регенерація, втрати тиску/тепла, генератор і власні потреби. Витрати — сумарні для контурів, не для однієї петлі/парогенератора. Це навчальна теплова схема; вона не відтворює реальну потужність ВВЕР або придатність конкретної турбіни до вологої пари.

### Формули

- Q = ṁ₁(hP2 − hP1) = ṁ₂(hS3 − hS2).
- hS2 = hS1 + (hS2s − hS1)/ηнасоса; sS2s = sS1.
- hS4 = hS3 − ηтурбіни(hS3 − hS4s); sS4s = sS3.
- Wтурбіни = ṁ₂(hS3 − hS4); Wнасоса = ṁ₂(hS2 − hS1).
- Qконденсатора = ṁ₂(hS4 − hS1).
- Wциклу = Wтурбіни − Wнасоса; ηциклу = Wциклу/Q.
- Перевірка: Q + Wнасоса − Wтурбіни − Qконденсатора ≈ 0.

При h у kJ/kg і ṁ у kg/s потужність виходить у kW. Малі нев’язки показують замикання обчисленого балансу, а не незалежну верифікацію реальної АЕС.

## Перевірки

`npm test` перевіряє баланс, масштабування потужності, недопустимі тиски/температури, обидві моделі, перерахунок імпортованих блоків, межі звіту, екранування тексту та сумісність JSON. `npm run test:study` перевіряє додавання п’яти типів блоків у браузері, порядок і пояснення, відновлення, HTML/PDF, JSON, англійську/українську, мобільний екран і автономний файл.

`npm run test:pwa`, `npm run test:hydraulics` і тести діаграм перевіряють відповідні сценарії після інтеграції. В установленій PWA нова збірка застосовується через «Встановлення та офлайн» → «Оновити програму» після публікації.
