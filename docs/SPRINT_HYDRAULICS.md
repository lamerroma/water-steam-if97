# Гідравліка круглої труби — 1.8.0

У вкладці «Витрати та Reynolds» оберіть «Втрати тиску та насос». Основні витрати залишаються доступними окремо; старі проєкти відкриваються без автоматичного ввімкнення гідравліки.

Задайте довжину L, внутрішній діаметр D, абсолютну шорсткість ε, суму місцевих опор Σζ і ККД насоса. Для потрібного напору можна додати різницю висот z₂−z₁ та різницю тисків P₂−P₁ на межах системи. Додатні значення збільшують напір, від’ємні зменшують. Різниця тисків не залежить від абсолютного чи манометричного відліку за однакового атмосферного тиску.

Властивості можна ввести вручну або отримати для рідини з поточного водяного ядра чи HEOS. Обчислення насоса не застосовується до відомих газових, парових, надкритичних або двофазних станів; для них доступний попередній розрахунок витрат. При ручному введенні користувач задає властивості нестисливої рідини.

## Методика

- Однофазна ньютонівська нестислива рідина, повністю розвинена течія в одній круглій трубі, сталі ρ та μ. Для ε/D використовується межа 0…0,05.
- Darcy–Weisbach: ΔPтер = λ(L/D)ρw²/2; ΔPмісц = Σζρw²/2. Усі ζ стосуються середньої швидкості в заданій трубі. Для різних перерізів потрібен окремий розрахунок.
- Re < 2300: λ = 64/Re. Re ≥ 4000: Colebrook–White, 1/√λ = −2log₁₀(ε/(3,7D) + 2,51/(Re√λ)); корінь знаходиться бісекцією.
- 2300 ≤ Re < 4000: коефіцієнт тертя не задається. При L > 0 сумарні втрати, напір і потужність показані як недоступні. Місцеві втрати обчислюються за введеним Σζ. При L = 0 тертя відсутнє.
- λ — Darcy, коефіцієнт Fanning = λ/4. Це різні визначення одного опору.
- Hвт = ΔP/(ρg); Hпотр = Hвт + Δz + ΔPмеж/(ρg), g = 9,80665 м/с². Швидкості на межах однакові, тому їх різниця кінетичних напорів дорівнює нулю.
- Hнас = max(0, Hпотр); Nгідр = ρgQHнас; Nвал = Nгідр/η. Від’ємний баланс явно пояснюється як надлишок енергії; потужність насоса не стає від’ємною.
- За нульової витрати втрати й потужність нульові; λ не визначається. Статичний потрібний напір може залишатися ненульовим.

Джерела формул: [DOE-HDBK-1012/3-92, модуль Fluid Flow, Head Loss / Bernoulli](https://www.energy.gov/documents/doe-hdbk-1012-92vol3) та [NASA/TM–2013–217492, GFSSP, pipe flow / Colebrook](https://ntrs.nasa.gov/api/citations/20140003178/downloads/20140003178.pdf). Межі режимів 2300/4000 прийнято як умовну класифікацію модуля; перехідну область не інтерполюємо.

Це визначення потрібного напору за заданою витратою, без підбору конкретного насоса. Кавітація/NPSH, стислива й двофазна течія, зміна температури/густини/фази вздовж труби, мережі, пучки труб і характеристики насоса потребують окремих моделей. Задані робочі властивості не визначають кінцевий термодинамічний стан автоматично.

## Контрольні навчальні приклади

Обидві кнопки у формі завантажують усі потрібні параметри й запускають розрахунок. Це власні навчальні задачі зі штучно заданими властивостями ρ = 1000 кг/м³ та μ = 0,001 Па·с, η = 80%, без підйому й різниці граничних тисків.

| Параметр | Ламінарний | Турбулентний |
|---|---:|---:|
| D, м | 0,01 | 0,05 |
| w, м/с | 0,1 | 2 |
| L, м | 10 | 100 |
| ε, мм | 0 | 0,05 |
| Σζ | 0 | 3 |
| Re | 1000 | 100000 |
| λ Darcy | 0,064 | 0,02217453594 |
| ΔPмісц, Па | 0 | 6000 |
| ΔPзаг, Па | 320 | 94698,14378 |
| Hвт, м | 0,03263091882 | 9,656523255 |
| Nвал, кВт | 0,000003141593 | 0,4648484263 |

Ламінарний контроль незалежно перевіряється законом Hagen–Poiseuille: ΔP = 128μLQ/(πD⁴). Для турбулентного прикладу перевіряється залишок рівняння Colebrook та баланс потужності. Допуск програмних контрольних чисел 10⁻⁹ відносно max(1, |значення|) — перевірка реалізації, не фізична точність кореляції.

## Збереження та перевірки

CSV містить втрати, напір, потужності, ККД, геометрію, граничні різниці та примітки. Значення експортуються без округлення, недоступні — порожні комірки. JSON розрахунку й спільний проєкт зберігають введені параметри й одиниці; результат перераховується, імпортовані обчислені властивості не використовуються. Формат JSON лишається сумісним із попередніми версіями.

```
npm run build
npm test
npm run test:hydraulics
npm run test:pwa
```

Браузерні перевірки охоплюють два приклади, конвертації, висотний і тисковий напір, імпорт/автовідновлення, мови, CSV, перехідну течію, нульовий потік, неправильний ККД, воду/пару, мобільний екран та автономний HTML. Для Playwright підтримуються `PLAYWRIGHT_MODULE_PATH`, `CHROMIUM_PATH`, `CALCULATOR_URL`.
