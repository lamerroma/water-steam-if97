# R16.1: реєстр доступного API ht / fluids

Робочий кандидат **1.41.0**, build `6dad6820c40a`. На момент цього етапу
опубліковано [1.40.0](../RELEASE_STATUS_UK.md). R16.1 додає рекурсивний каталог,
відтворюваний реєстр і перевірки його цілісності. **R16 загалом ще відкритий**:
повні контракти, optional-варіанти та динамічний стан класів не прийняті.

## Спостережений обсяг

| Зафіксований пакет | Публічні шляхи | Об'єкти функцій/класів | Базові сімейства без vectorize | Прив'язки даних | Класи | Статичні члени класів |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| ht 1.2.0 | 858 | 510 | 255 | 93 | 0 | 0 |
| fluids 1.3.1 | 2636 | 1396 | 878 | 585 | 35 | 382 |

[surface.json](surface.json) містить **3494 шляхи та 2966 записів**:
1871 функція/обгортка, 35 класів, 678 прив'язок даних і 382 статичні члени.
Aliases одного callable об'єднано за ідентичністю об'єкта в процесі; зв'язок
`numpy.vectorize → pyfunc` збережено окремо. Дані з однаковим значенням не
об'єднуються. **1133 базові сімейства — не 1133 незалежні фізичні алгоритми**:
вони включають допоміжну математику й імпортовані функції.

Попередній однорівневий каталог fluids мав 2252 рядки, з них 2242 унікальні
шляхи. Рекурсивний обхід прибрав 10 повторів того самого шляху та відкрив
**394 додаткові шляхи**; псевдоніми з різними шляхами збережено. Змінені
шляхи доступні через той самий JSON-інтерфейс, зокрема офлайн. Wheels не змінено.

## Що саме зафіксовано

- Стабільний ID `package@version:canonical.path`, aliases, тип, сигнатура,
  джерело з SHA-256/рядком, docstring, імпорти та зв'язки обгорток.
- Статичні члени без виконання getter. AST показує 424 кандидати `self.attr`;
  це не повний перелік доступних атрибутів реальних екземплярів.
- Усі 71 Python-файл pinned-пакетів мають хеші. Перед генерацією перевіряються
  всі 93 файли встановлених ht/fluids проти незмінених wheels, включно з даними.
- Шість недоступних модулів: `numba`, `numba_vectorized`, `units` у кожному
  пакеті. Їхні джерела/імпорти збережено; динамічно створені експорти ще не
  перелічені. Їх не вилучено з кінцевої цілі й не зараховано як прийняті.
- [Native](runtime-signatures-native.json) та
  [Pyodide](runtime-signatures-pyodide.json) профілі зберігають сигнатури
  залежностей/runtime окремо. Виявлено 11 відмінних записів між CPython 3.12
  і 3.14, переважно успадковані методи винятків та `functools.wraps`.

Стадії каталогу, типів, одиниць, геометрії, домену, залежностей, числового
приймання, UI, збереження, експорту й холодного офлайн-запуску розділені.
Генератор позначає невстановлене `unreviewed` / `null`. Одиниці з docstring
залишаються спостереженням, а не перевіреною схемою або безрозмірністю.

[reviewed-contracts.json](reviewed-contracts.json) містить **п'ять часткових
описів**: LMTD, Reynolds, dP_from_K, det і TANK. Вони прив'язані до SHA джерела,
описують лише зазначений піднабір і не надають числового приймання.
Це описи для розробки, ще не повні виконувані JSON Schema для всього API.

## Підтверджені розбіжності та попередження

1. `fluids.numerics.arrays.det([[7]])` повертає `[7]`; математичний еталон
   залишається скаляром `7`. [Контролі](controls.json) містять **три збіги та
   одну відому розбіжність**, а не чотири числові PASS. UI, `describe`, відповідь
   Worker і JSON-експорт показують `fluids-det-rank2-1x1`.
2. `ht.LMTD(100, 99.999999999, 30, 30.000000002, counterflow=True)` повертає
   `70.00040412254486 K`; Decimal-логарифмічне середнє кінцевих різниць
   приблизно `69.9999999985 K`. Втрата точності близько `0.000404124 K` явно
   позначена `ht-lmtd-nearly-equal`, також для vectorized-обгортки.
   Це окремий діагностичний випадок, не оцінка всієї похибки LMTD.

Сирі відповіді upstream збережено. Предметна форма R17 має окремо узгодити
чисельно стійкий варіант, область фізично допустимих входів і provenance.

## Відтворення й докази

Native-середовище: Python 3.12, NumPy 2.5.4, SciPy 1.18.1 та локальні wheels
ht/fluids. Browser: pinned Pyodide/CPython 3.14.2, NumPy 2.4.6, SciPy 1.18.0.

```sh
python -m pip install -r scripts/reference/requirements-library-registry.txt
python scripts/generate-library-registry.py
python scripts/reference/test_library_registry.py
npm run verify:library-registry
npm run test:library-registry:browser
npm run test:python-libraries
```

У Windows задайте `PYTHONUTF8=1`; для Firefox — `BROWSER_NAME=firefox`.
`generate:library-registry` / `--write` оновлює реєстр після явного перегляду
змін. Звичайний запуск нічого не переписує і відхиляє розбіжності.

Спільний collector порівняно цілком у CPython та обох браузерах: шляхи,
групи ідентичності, pinned-сигнатури, джерела, документи та члени збігаються.
Окремий справжній UI-сценарій в обох браузерах пройшов 11 груп: виклики,
попередження, об'єкти, масиви, скасування, пошкоджений кеш і новий запуск без
сервера. Див. [машиночитний підсумок](acceptance.json) та
[браузерні докази](evidence/chromium-registry.json).
Це інтеграційна перевірка; збіг CPython/Pyodide не є незалежною фізичною валідацією.

Повні початкові журнали, включно з невдалими дослідними запусками, залишено
локально у `.release/development-r16/` і `.release/library-registry/`.
Первинна відмова на `det([[7]])` збережена; еталон `7` не змінено.
[Ліцензії документації та вкладених джерел](UPSTREAM_NOTICES.md).

## Залишок R16.2 та наступні роботи

Потрібно завершити reviewed-контракти типів/одиниць/геометрій/доменів,
серіалізацію аргументів і життєвий цикл класів, класифікацію джерел/кореляцій,
рішення щодо шести optional-модулів, і прив'язки конкретних випадків до
тестів/експорту/предметного UI. Загальний числовий відсоток залишається `null`.

R21/R26 плануються від сімейств та сценаріїв, даних і членів класів окремо;
aliases не множать предметний обсяг. Наявні 20/45/90 та 25/55/110 інженерних
днів — **початкові сценарні резерви**, ще не нова виміряна оцінка. Відсутній
знаменник optional-варіантів і немає виміряної швидкості приймання перших 20
методів, тому множити ці дні на відношення розмірів каталогів було б хибно.
Після R16.2 і перших предметних форм R17/R22 слід переоцінити залишок у
[повному плані](../DEVELOPMENT_MASTER_PLAN_UK.md).
