# Перевірка функцій калькулятора після переходу на PWA

Дата: 22.10.2026. Кандидат виправлення **1.40.1 / `5b5173c2a5cf`** на базі
опублікованої 1.40.0. Нові модулі кандидата 1.41.0 до цього виправлення не входять.
[Вхідні дані, підсумки та SHA-256 доказів](pwa-legacy/acceptance.json).
Це датований протокол окремої 1.40.1; SHA джерел стосуються саме її,
а не всіх файлів робочого кандидата 1.41.0. Обидва виправлення перенесено
також у гілку розробки.

## Знайдено та виправлено

1. Після пакетного розрахунку селектор формату експорту `batch-spreadsheet-format`
   потрапляв у розрахункові входи проєкту. Читач відхиляв власний JSON із
   повідомленням «Некоректні дані вкладки batch.». Це відтворено також у 1.35.12:
   помилка існувала до міграції. Нові snapshots містять поля форми та CSV-текст;
   історичні відомі значення xlsx/ods/xls/csv приймаються й вилучаються з входів.
   Невідомі поля та некоректні значення й надалі відхиляються.
2. У робочому кандидатові PWA, Firefox 153 на Windows, швидкий перехід T–s → h–s → P–h → довідка
   під час фонового уточнення діаграми аварійно завершував вкладку. Короткий
   сценарій відтворено окремо, з газовим розрахунком і без нього. При очікуванні
   завершення уточнення збою не було. Runner тепер одразу відхиляє застарілий
   запит, уточнення отримує сигнал скасування, а стандартний Worker завершується після
   кінцевої відповіді, наступною задачею циклу подій. Є watchdog 120 с для
   Worker, що не відповідає. Ізольований HEOS зберігає окрему політику завершення.
   Після виправлення перевірено 10 онлайн і 5 холодних офлайн-циклів на браузер,
   а також по два детерміновані скасування активного уточнення з підтвердженою
   відповіддю cancelled та фактичним завершенням Worker.
   Це локальне відтворення, а не встановлення внутрішньої причини збою Firefox.
   Короткий окремий контроль публічної 1.40.0 пройшов успішно; він не
   відтворює цей збій на публічній версії й не доводить його відсутності.

## Обсяг перевірки

Усі 30 розділів старої 1.35.12 (`6bae913`, build `8976baaf14e1`) присутні;
у PWA додано 31-й розділ бібліотек. Розрахунки перевіряються через форми,
Worker та відображені/експортовані результати. Дані старого прикладу створені
тестом у чистому профілі; це не особистий проєкт користувача.

| Група | Перевірено |
| --- | --- |
| Вода та насичення | P–T, насичення за p, таблиця насичення, порівняння моделей |
| Речовини | Реальний газ, NASA7, BSW2003; чотири входи вологості; лід; D2O P–T і насичення; морська вода; плавлення й сублімація |
| Процеси | Турбіна, флеш, насос, компресор, теплообмінник, простий процес і редактор циклу |
| Цикли | Ренкін, перегрів, регенерація, Брайтон, схема АЕС |
| Допоміжні функції | Гідравліка, LMTD, навчальний приклад, лабораторна, чотири режими курсової, дослідження, пакетна серія |
| Діаграми та навігація | T–s/h–s/P–h, довідка, проєкти й звіт; повторний перехід до основного калькулятора |
| Дані та офлайн | Справжній старий JSON, дев’ять відновлених панелей, range/CSV, новий експорт, закриття профілю та повторний запуск без мережі |

Точні кількості зіставлень і величин наведені у acceptance.json. Порівнюються
однакові входи; негативний контроль насоса з парою фіксує очікувану відмову.
Повторення одного прикладу й точки розрахованого профілю не є незалежними
експериментальними еталонами. Перший повний CI виправлення (попередня збірка f52a3c42e921) мав 108/110 PASS:
два нові сценарії не гарантували незавершений запит на швидкому Linux.
Оновлений сценарій запускає реальне масштабування, виходить під час
передавання запиту й перевіряє terminal reply та закриття Worker. Додатковий
стрес-тест на Windows показав недостатність простого відкладання terminate;
тому додано кооперативне скасування. Невдалі журнали збережено. Повторний
повний CI точного кандидата обов’язковий перед публікацією.

## Що не підтверджено

Це обмежений відтворюваний аудит, а не доказ правильності всіх можливих входів.
Збіг зі старою програмою перевіряє регресії; незалежні числові й фізичні еталони
обліковуються окремо. P03/P04 Steam97Web мають 20 Registration Required і нуль
числових результатів оригіналу. Нейтронна комірка має physical-screening-failed;
P04 та повне числове приймання ht/fluids залишаються дослідними/відкритими.
Фізичні мобільні пристрої та Safari не перевірялися. Попереднє окреме
спостереження Firefox під час масових P08-експортів не оголошено виправленим.

## Відтворення

Основна PWA має бути запущена через HTTP/HTTPS; `CALCULATOR_URL` задає адресу.
Для поточних регресій достатньо `npm run test:legacy-project` та
`npm run test:diagram-navigation`. Для Firefox задайте `BROWSER_NAME=firefox`.
Обидва регресійні сценарії включено до повного release-приймання.

Для диференційного аудиту потрібен локальний Git-об’єкт `6bae913...`.
У PowerShell: `$env:LEGACY_ROOT = python scripts/prepare-legacy-audit.py`,
потім `npm run audit:pwa-legacy`. Підготовка перевіряє всі байти архіву та
зберігає змінену історичну копію без перезапису. Старий standalone.html у цій
ігнорованій копії є еталоном історії, а не поверненням однофайлового застосунку.
Сирі журнали й невдалі спроби збережено у `.release/functional-restore/`.

Окремий сценарій оновлення зі справжньої 1.40.0 з пакетною серією:
`node docs/pwa-legacy/upgrade-legacy-batch.cjs`, із `PWA_BASELINE_ROOT` до
перевіреної папки `dist` цієї старої версії. Він перевіряє старе поле
формату, десять повторно розрахованих рядків, одиниці, історію, мову,
підготовлений Python-пакет, HEOS і ht.LMTD після холодного офлайн-запуску.
Це локальний сценарій одного origin; фактична публікація має окремі докази.

Під час CI 18a0dc5 підготовка браузерів затрималася на завантаженні
системних пакетів Azure-дзеркала Ubuntu. Перший запуск скасовано вручну;
до фактичної зупинки він уже почав unit-тести. Повторна підготовка також
затягнулася. Для наступного запуску CI використовує офіційні дзеркала
Ubuntu через HTTPS, APT timeout/retries і окремі обмежені кроки встановлення
залежностей та браузерів. Перевірка підписів APT, pinned Playwright і всі
перевірки застосунку збережені. Це зміна CI; runtime build лишається тим самим.
