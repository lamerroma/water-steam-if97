## Що реалізовано

У проєкт додано обмежене поле `libraryRecipe` з вхідним текстом. Читач проєкту
не викликає Python і не відновлює збережені числа сценарію. Старі проєкти
отримують порожній текст. Незавершений JSON залишається чернеткою; імпорт
окремого сценарію перевіряє структуру до заміни поточного тексту.

Виконавець знімає копію входів, перевіряє версії й залежності, послідовно
розв'язує логічні посилання та використовує новий окремий runner/Worker.
Він завершує Worker за будь-якого виходу. Помилка або скасування зупиняє
решту кроків. Динамічні outputs і стан об'єктів не є даними відновлення проєкту.
Звіт містить pinned-версії, єдину ревізію Worker, upstream-одиниці та попередження;
опис об'єкта позначено `object-summary`.

Рецепти допускають публічні `call/get/release`, попередні значення й об'єктні
аргументи, але не довільний Python-текст. Для повторного використання типізованих результатів
в аргументах потрібні відповідні явні вхідні теги. Передані JSON-словники не стають Python-об'єктами
через випадкове поле `kind`; живий handle визначає тільки поточний Worker.
Це контракт повторення команд, не загальна серіалізація Python-графа або
гарантія детермінованості випадкових/зовнішньо залежних функцій.

## Контрольний піднабір

Перевірено вертикальний прямий циліндр TANK, D=1 або 2 м, L=2 м, h=0,5 м:
конструктор, V_total, V_from_h, h_from_V. Окремий D=1 випадок змінює таблицю
через set_table(n=3) та читає volumes. Одиниці і точні входи наведено в контракті.
Аналітичні еталони — геометрія `V=πD²h/4`, а не копія результатів бібліотеки.
Це арифметичні й інтеграційні контролі вибраної геометрії, не загальна
фізична або числова валідація TANK.

Браузерний сценарій також перевіряє cold cancel, зупинку на помилці,
невідповідність ревізії пакета, редагування й навігацію під час запуску,
асинхронний імпорт, UK/EN та 390 px, збереження й імпорт цілого проєкту,
холодний перезапуск офлайн та втрату Python-кешу. Окремий raw-сценарій
перевіряє, що новий Worker не анулює вже створений raw-об'єкт.

```sh
npm test
npm run verify:library-recipes
npm run test:library-recipes
```

Для Firefox задайте `BROWSER_NAME=firefox`; Playwright потрібен тільки перевіркам.
CI запускає обидва браузери. Сирі попередні та остаточні журнали залишено
в `.release/development-r16-3/`; керовані вибрані докази — в `evidence/`.

## Локальне приймання 22.10.2026

Кандидат 1.41.0 / `9df70046fd91`: 1827/1827 модульних тестів на Node 22
і окремо на Node 24; у Chromium 151 та Firefox 153 — по 15 груп сценаріїв
і 14 груп чинної Python-панелі. На браузер перевірено 12 скалярних
геометричних значень і три точки зміненої таблиці.
Збірки Node 22/24 побайтово однакові; ZIP відтворюється й проходить
незалежний ZIP-reader. [Машиночитні докази](acceptance.json) пов’язують
джерела, контракт, приклад, звіти й чотири скриншоти через SHA-256.
Повний CI нового коміту запускається після push; попередній зелений CI
не є прийманням нового коду. Публічна 1.40.0 залишається окремим релізом.
