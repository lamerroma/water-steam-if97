# Незалежна числова перевірка курсової ЯЕР — 1.16.1

## Результат і його значення

Додано окрему реалізацію на Python без імпорту JavaScript-коду калькулятора. Вона звіряє 45 варіантів, кільцеве паливо з чохлом, ручний інтеграл і ефективність стрижня, сталі теплопровідності, координати, кільця та IAPWS-95: загалом 51 набір даних.

[Машинний протокол](REACTOR_NUMERICAL_AUDIT.json) містить кількість порівнянь, найбільші відхилення кожного набору та SHA-256 перевірених джерел. Допуск — 2·10⁻⁸ відносно результату, з масштабом не менше 10⁻¹² біля нуля. Розбіжність, неповний результат або помилка Python завершують перевірку з ненульовим кодом.

Перевіряються:

- геометрія ТВЗ й активної зони, витрата, потужність та піковий лінійний потік;
- Reynolds середнього стану, тертя пучка, місцеві втрати, підйом, прискорення й сума перепаду;
- баланс збагачення зон, концентрації, нейтронна температура, резонансний інтеграл, поправка Доплера, поглинання, гранична поправка, k∞/kеф, дифузія, вік і витік для гарячого та холодного станів;
- ефективність центрального стрижня, ваги Бесселя для заданого розташування, сумарний Δk, елементний бор і борна кислота;
- нейтронний коефіцієнт на початку, в середині та наприкінці горизонту кампанії;
- тепловіддача, температури всіх шарів та CHF у трьох осьових точках: вхід, центр, вихід. Python використовує окреме розв'язання температурних рівнянь.

**Це незалежна реалізація арифметики обраної навчальної моделі, а не експериментальний еталон реактора.** Спільними залишаються властивості води з IF97/IAPWS-95, середні температури води й палива як граничні дані нейтронної частини, таблиці поправок і навчальні константи. Python не перевіряє їх фізичну достовірність; осьове усереднення та корінь кампанії перевіряються звичайними тестами, а не цим протоколом. Погодження двох реалізацій не усуває помилок спільної методики.

## Як відтворити

Потрібні Node.js 20+ і Python 3 (лише стандартна бібліотека):

```bash
npm run verify:reactor
node scripts/verify-reactor-reference.mjs --write-report
```

За потреби шлях до Python можна вказати змінною середовища `REACTOR_PYTHON`. Команда без `--write-report` перевіряє поточний код і не змінює файлів. Протокол потрібно оновлювати після змін формул чи констант. Перевірка виконується під час розробки; браузерний додаток не потребує Python.

## Що з'ясовано за джерелами

1. **Квадратна гранична поправка:** у наданій методичці після відповідного речення є вираз для гексагональної решітки. Підтвердженого виразу для квадратної у переглянутих матеріалах не знайдено. Значення γ вводиться явно і тепер показується окремо для обох нейтронних станів та серед формул у записці. Типове γ = 1 залишається припущенням; узгоджена формула потрібна від викладача.
2. **Кипіння:** методичка одночасно містить критерій `tоб > tнас + 5 K`, критерій перевищення потоку початку кипіння і приклад з протилежним знаком різниці потоків. Публікація [Pronobis та Litka, 2012, Eq. (1)](https://journals.pan.pl/Content/84718?format_id=1) підтверджує одиниці бар/Вт·м⁻² та межу 8…20 МПа для базового закону кипіння, але не всю комбіновану модель пучка. Тому підтверджено одиниці й окремий закон, а повна поправка залишена явно позначеною інтерпретацією.
3. **CHF:** показники перевірено за [Lys та ін., 2021, Eq. (15)](https://vant.kipt.kharkov.ua/ARTICLE/VANT_2021_5/article_2021_5_88.pdf). У цій публікації додатково є коефіцієнт форми потоку fF, Eq. (16). Наш режим використовує fF = 1, як базовий навчальний розрахунок; він не відтворює повну систему контролю реактора з публікації. Межі фізичної застосовності до довільної геометрії не підтверджені.
4. **Повний фізичний еталон:** помилки Excel `#NAME?` і суперечливі ручні числа не можна використати як контрольну відповідь. З'явилася незалежна числова реалізація; для остаточної фізичної перевірки потрібен погоджений повний розрахунок із джерелами всіх констант.
