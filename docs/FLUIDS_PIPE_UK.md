# Перевірка трубопроводу через fluids — 1.39.0

## Використання

«Теплообмін і гідравліка» → «Витрати, Reynolds та гідравліка».
Увімкніть втрати тиску й насос; у «Порівняння з fluids» виберіть Clamond
або Colebrook. Для прямого виклику fluids потрібен підготовлений пакет Python
у «Бібліотеки ht / fluids». Без нього форма пояснює причину відмови;
«Без перевірки fluids» залишає чинний локальний JS-розрахунок.

Доступні ручні ρ/μ або ν, властивості води/пари IF97/IAPWS-95 та CoolProp.
Для гідравліки допускається лише однофазна нестислива рідина. Вода автоматично
дає ρ та μ для введених абсолютного тиску й температури. Діаметр внутрішній.
Одиниці витрати, діаметра, довжини, шорсткості та властивостей переводяться
формою в SI до виклику Python. ΣK задається користувачем і відноситься до
швидкості в цій трубі; автоматичного підбору арматури поки немає.

Результат містить власний розрахунок та окрему таблицю fluids / JS / різниця.
Таблиця порівняння завжди в SI, незалежно від загальних перемикачів одиниць.
Це прямий виклик незміненої fluids 1.3.1 у Python Worker. CSV і JSON зберігають
числа без екранного округлення, нормалізовані входи, вибраний метод, одиниці,
версію бібліотеки й результат порівняння. JSON також містить ревізію реалізації. JSON-проєкт
відновлює вхідні дані та повторно обчислює результат; вкладеним збереженим
числам не довіряє. Вимкнення або скасування не означає успішної перевірки.

Навчальний звіт продовжує відтворювати власний JS-розрахунок. Порівняння
з fluids експортуйте через CSV/JSON самої панелі; воно явно відділене від
чисел навчального звіту. Обидві частини позначені в інтерфейсі.

## Контракт і межі

Метод протоколу: `fluids / pipe-hydraulics`. Нормалізовані входи:

| Вхід | Одиниця / умова |
| --- | --- |
| rho, mu | кг/м³, Па·с; >0 |
| velocity, diameter | м/с ≥0; м >0 |
| length, roughness | м ≥0; ε/D ≤0,05 |
| localK | безрозмірний, ≥0 |
| efficiency | частка, 0<η≤1 |
| heightDifference | z₂−z₁, м |
| pressureDifference | P₂−P₁, Па; це різниця, не абсолютний тиск |
| frictionMethod | Clamond або Colebrook |

Публічні функції: `fluids.Reynolds`, `fluids.friction_laminar`,
`fluids.friction_factor(..., Darcy=True)`, `fluids.dP_from_K`.
Додатково перевірено `fluids.one_phase_dP` як upstream-контроль, але він
не викликається цією формою: його автоматична межа режиму відрізняється.

Політика застосунку:

- Re=0: тертя не визначено, втрати та потужність нульові; статичний напір
  може бути ненульовим.
- 0<Re<2300: λ=64/Re через `friction_laminar`, незалежно від вибору Clamond/Colebrook.
- 2300≤Re<4000: λ, тертя й сумарні втрати/потужність недоступні (`null`).
  Місцеві втрати за заданим K відомі; якщо L=0, відомі й повні втрати.
- Re≥4000: обраний метод із `friction_factor`, коефіцієнт Darcy, не Fanning.

λFanning=λDarcy/4; ΔP=(λL/D+ΣK)ρw²/2; Hвт=ΔP/(ρg).
Hнас=max(0,Hвт+Δz+ΔPмеж/(ρg)); Nвал=ρgQHнас/η; g=9,80665 м/с².
Від'ємний баланс не породжує від'ємну насосну потужність.
Відсутні величини не замінюються нулями. Переповнення, нечислові значення,
невідомі поля й методи відхиляються.

Це модель сталих властивостей і розвиненої течії в прямій круглій трубі.
Стисливість, зміна густини вздовж труби, нагрівання, кавітація, двофазність,
мережі, різні швидкості на межах системи та двигунний ККД не моделюються.
Задані K мають відповідати реальній арматурі та режиму.

## Спостережена різниця upstream-політики

У незміненій fluids `friction_factor` повертає 64/Re тільки при Re<2040,
далі застосовує вибраний турбулентний метод. При Re=2200, ε/D=0 спостережено:
`friction_factor` = 0.047957892001719564, `friction_laminar` = 0.02909090909090909.
Форма свідомо зберігає власну явну політику 2300/4000. Це різниця умов
виклику, а не помилка арифметики бібліотеки. Межа переходу фізично не є
універсальною точною сталою.

## Незалежний числовий контроль

`scripts/reference-fluids-pipe.py` використовує тільки Python stdlib Decimal,
80 значущих цифр, 240 кроків бісекції Colebrook у змінній y=1/√λ,
Hagen–Poiseuille та баланс енергії. Він не імпортує fluids або наш JS-код.
Fixture: `tests/fixtures/fluids-pipe-reference.json` — 100 випадків і
16 некоректних входів. Обидва методи; ламінарні та перехідні межі; гладкі й
шорсткі труби; Re до 10¹⁰; ε/D до 0,05; нуль, L=0, висота й тиск.
Великі Re є числовим стрес-контролем формул, а не підтвердженням практичної
нестисливості такого потоку.

На узгодження використано |a−b| ≤ 1e−10 + 5e−11·max(|a|,|b|).
Це допуск числового відтворення рівнянь, не оцінка фізичної похибки моделі.
Точні протоколи й результати завершених запусків: `fluids-pipe/` поруч із цим
документом, підсумок — `FLUIDS_PIPE_ACCEPTANCE_UK.md`.

Підтверджено й виправлено окрему помилку власної форми: задана швидкість
перераховувалася через масову витрату назад у швидкість; при ρ=μ=D=1,
w=4000 результат Re міг стати трохи меншим за 4000. Прямо задана швидкість
тепер зберігається, без додаткового округлення чи довільного зсування меж.

Команди: `npm run audit:fluids:pipe`, `npm test`, `npm run test:fluids-pipe`.
Для Firefox задайте `BROWSER_NAME=firefox`. Перевірку fixture включено до core
release; браузерний сценарій — до повного release для обох браузерів.

Це приймання обмеженого гідравлічного workflow. Воно не підтверджує всі функції
fluids/ht, експериментальну точність кореляцій або відповідність Steam97Web.
Наступні етапи: арматура з явними методами K та теплообмінні кореляції ht.

Першоджерела: [fluids friction](https://fluids.readthedocs.io/fluids.friction.html),
[fluids core](https://fluids.readthedocs.io/fluids.core.html).
Зафіксований первинний код і ліцензія збережені в незміненому wheel 1.3.1,
його SHA-256 — у `vendor/python/manifest.json`. Python-обгортка є кодом застосунку.
