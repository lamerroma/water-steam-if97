# Вибір параметрів і перевірка введення — 1.6.0

## Як користуватися

У головному калькуляторі оберіть перший і другий відомі параметри. Програма визначає відповідний режим з наявних 20: 18 пар і насичення за тиском або температурою. Другий список містить лише підтримувані поєднання. Для P–T можна спочатку вибрати температуру, потім тиск; кнопка ⇄ міняє порядок полів без зміни фізичного стану. Для насичення оберіть тиск або температуру та «Насичення — обидві фази».

Біля кожного поля є власний вибір одиниць. Зміна одиниці перераховує число. Під час зміни пари введені значення та одиниці відомих величин зберігаються; останні значення тимчасово вилучених величин пам’ятаються в поточному сеансі. Нові величини отримують стандартні значення, які потрібно звірити з умовою задачі. Після імпорту іншого проєкту тимчасова пам’ять очищується.

«Розширений режим» відкриває попередній список усіх функцій. Перемикання способу введення зберігає поточні числа й одиниці; у розширеному режимі порядок канонічний. Швидкі кнопки P–T, P–h, P–s і насичення залишилися доступними.

## Перевірка полів

Після виходу з поля, зміни одиниці або спроби розрахунку перевіряються:

- порожні значення, нечисловий текст, нескінченність та переповнення;
- межі тиску й температури обраної моделі; для IF97 також обмеження 50 МПа за T > 800 °C;
- окремі межі насичення, сухість у частках або відсотках;
- додатність густини та питомого об’єму.

Помилка показується під відповідним полем, поле отримує `aria-invalid` і зв’язок з поясненням через `aria-describedby`. Після невдалої спроби розрахунку фокус переходить до першого помилкового поля у видимому порядку. Нові помилкові стани не додаються до журналу. Числа приймають кому, крапку й експоненційний запис, але не розділювачі тисяч. Текст не вставляється як HTML.

Межі простих параметрів наведені у вибраних одиницях. Тиск перевіряється після переходу до абсолютного значення: допустимий від’ємний манометричний тиск не відкидається автоматично. Складне обмеження області 5 пояснюється в абсолютних МПа та °C. Для h, s, u не вигадуються довільні межі; наявність стабільного стану й чисельну збіжність перевіряє ядро. Такі повідомлення залишаються загальними.

На лінії насичення P–T не визначає склад суміші. Калькулятор показує обидві фази та пояснення з діями «Задати сухість» і «Показати насичення за тиском». Перехід до сухості зберігає введений тиск і ставить фокус у поле x; стандартне x потрібно замінити значенням з умови задачі.

## Збереження й сумісність

Розрахункові `mode`, `a`, `b`, `ua`, `ub` у JSON залишилися канонічними. Порядок на екрані не змінює формули, джерела станів, CSV чи передачу станів на діаграми. Додано необов’язкові `form.inputStyle` (`smart`/`advanced`) та `form.inputOrder` (`canonical`/`reverse`). Старі проєкти відкриваються у виборі параметрів із канонічним порядком. Версія формату JSON не змінена; неправильні значення нових полів відкидаються до застосування проєкту.

Поточна пара, одиниці, числа та спосіб введення зберігаються автоматично й у JSON. Українська, англійська, мобільний екран та автономний файл підтримуються. Математичне ядро не змінювалося; будь-які обмеження або неоднозначність обраної моделі зберігаються.

## Перевірки

```bash
npm run build
npm test
npm run serve
# У другому терміналі з Playwright і Chromium:
npm run test:smart-input
npm run test:diagrams
```

Для окремого runtime підтримуються `PLAYWRIGHT_MODULE_PATH`, `CHROMIUM_PATH`, `CALCULATOR_URL` (новий сценарій) і `DIAGRAM_URL` (діаграми). Нові тести перевіряють відповідність усіх 20 режимів, обидва порядки пар, конвертації, межі моделей, манометричний тиск, валідацію, неоднозначне насичення та сумісність JSON. Браузерна перевірка охоплює введення, розрахунок, мови, помилки, авто-відновлення, імпорт старих/нових проєктів, екран 390 px та офлайн-файл. Регресія діаграм перевіряє журнал → графік → експорт і передачу станів назад у калькулятор.
