# Спринт 1.33.0 — ККД обладнання Ренкіна

У бібліотеці простого Ренкіна та Ренкіна з одним проміжним перегрівом доступні «Ідеальне» й «Задані ККД» обладнання. Задаються ізоентропні ηнасоса, ηтурбіни/ЦВТ та, для перегріву, ηЦНТ у частках: 0 < η ≤ 1. IF97 та IAPWS-95; докритичний котел, насичена рідина після конденсатора, перегрітий або сухий насичений вхід. Втрати тиску, регенерація й надкритичні рецепти не входять до спринту.

## Фізична модель

Для кожного агрегату незалежно визначається ізоентропний вихід за його власними вхідною ентропією та вихідним тиском. Насос: h₂ = h₁ + (h₂ₛ − h₁)/ηнасоса. Турбіна: hвих = hвх − ηтурбіни·(hвх − hвих,ₛ). Реальний вихід обчислюється за p,h; насос має залишатися стисненою рідиною. Всі стани й інверсії повинні належати області моделі, без неоднозначних коренів. Потрібні додатні підведення тепла та корисна робота двигуна; перегрівач повинен підводити тепло після фактичного виходу ЦВТ.

Модель обладнання адіабатна: q = 0; wₜ = hвх − hвих; генерація ентропії sgen = sвих − sвх ≥ 0 (з числовим допуском 2×10⁻⁷ kJ/(kg K)). Кінетична й потенціальна енергія не враховані. Для циклу з таким обладнанням використовується баланс усталеного потоку та сума технічних робіт. Тепло ізобарних теплообмінників і далі визначається незалежним інтегруванням з незмінними критеріями точності.

Інтеграл T ds не є теплом необоротного обладнання; p–v-площа не є його роботою. Роботу розширення для агрегату не вигадано: boundaryWork = null. Нульовий алгебраїчний баланс обладнання не є незалежною перевіркою фізичної точності. Для перевірки є зовнішні еталони вихідних станів і компонентних робіт. δq/δwₜ у компонентній таблиці стосуються лише оборотних шляхів; для адіабатного обладнання ці клітинки порожні.

Сам ізоентропний ККД визначає вихідний стан, але не внутрішню траєкторію. Тому на всіх шести діаграмах показано лише штрихове **схематичне з’єднання входу й виходу**, з поясненням у результаті та SVG. Це не набір розрахованих проміжних станів. Обидва кінці перевірені рівнянням стану. Оборотні теплообмінники зберігають повні розраховані шляхи. Адіабатний агрегат з η = 1 дає ті самі кінцеві стани, що й ідеальний ізоентропний; невеликі відмінності сумарних інтегральних величин обмежені допусками.

## Інтерфейс і відтворення

Нова таблиця показує ηₛ, hвих,ₛ та генерацію ентропії кожного агрегату. Зберігаються наявні компонентні баланси, підсумок робіт/тепла/ККД, сухість і вологість. Для перегрітої пари x та 1−x залишаються невизначеними. Зміна вологості сама по собі не встановлює допустимість режиму турбіни.

Кнопка «Порівняти поточний Ренкін з ідеальним» формує A з ідеальним обладнанням та B з поточними перевіреними входами. Параметри A виводяться з поточних станів, включно з тисками, масою, моделлю, режимом насичення та температурами нагрівання, а не з незалежної чернетки генератора. Обидва варіанти заморожуються, відтворюються у звіті й мають шість суміщень у спільному масштабі. Подальші зміни B явно не змінюють A або збережений блок звіту.

Канонічний закон `adiabatic` з числовим `eta` зберігається на виході відповідного стану. Шаблони, JSON-проєкти, CSV та звіти зберігають ці входи, не довіряючи імпортованим результатам. Редактор показує n або ηₛ у відповідному рядку. Вихідні стани залишаються незалежними: зміна лише η без узгодження виходу дає помилку, а не тихий перерахунок іншого рядка. Для побудови нових узгоджених станів використовуйте генератор бібліотеки. Загальний генератор наступного стану для адіабатного рядка вимкнено; для простих законів він працює як раніше.

Старі проєкти без параметрів обладнання відкриваються в ідеальному режимі. Неактивний незавершений ηЦНТ не блокує простий цикл; неактивні ККД не блокують ідеальний режим. Зміна між газами й водою зберігає сумісність законів і моделей. Worker, скасування, захист від запізнілих результатів та останній готовий результат при хибному параметрі збережені.

## Незалежна перевірка

`tests/fixtures/rankine-actual-reference.json` містить 8 числових еталонів зовнішнього Python iapws 1.5.5: простий цикл, один проміжний перегрів, сухий насичений вхід, перегрітий вихід — кожен для IF97/IAPWS-95. Генератор: `PYTHONPATH=/path/to/isolated-install python3 scripts/generate-rankine-reference.py --actual`. Бібліотеки iapws, SciPy й NumPy у runtime не входять.

Ізоентропні виходи визначаються правилом важеля в області насичення або brentq за зовнішнім s(T,P). Для фактичних виходів — правило важеля за h або brentq за зовнішнім h(T,P), з перевіркою нев’язки < 10⁻⁶ kJ/kg. Числа застосунку не використовуються для генерації. Звіряються всі кінцеві стани, компонентні роботи/тепло, ККД, якість, межа η = 1 та генерація ентропії. Для 10 MPa / 773,15 K / 0,01 MPa з ηнасоса = 0,85 та ηтурбіни = 0,88: η установки IF97 ≈ 0,35294199; з перегрівом при 2 MPa до 773,15 K та ηЦНТ = 0,90 — ≈ 0,37761538. Це контрольні приклади, не універсальна закономірність поліпшення режиму.

Протокол приймання: [RANKINE_EFFICIENCY_ACCEPTANCE.json](RANKINE_EFFICIENCY_ACCEPTANCE.json). Публікація виконується окремо після перевірок.
