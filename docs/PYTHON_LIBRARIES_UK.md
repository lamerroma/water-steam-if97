# Бібліотеки ht / fluids — локальна інтеграція 1.38.0

## Що підключено

Незмінені Python-бібліотеки виконуються у браузері через окремий module Worker.
Сервер розрахунків не потрібен; CDN/PyPI не використовуються під час виконання.

| Компонент | Зафіксована версія |
| --- | --- |
| ht | 1.2.0 |
| fluids | 1.3.1 |
| Pyodide / CPython | 314.0.7 / 3.14.2 |
| NumPy / SciPy | 2.4.6 / 1.18.0 |

Пакет: 14 файлів, 31 973 269 байтів. Походження, SHA-256, розміри та ліцензії:
`vendor/python/manifest.json`. Відтворення: `npm run vendor:python`.
Збірка копіює пакет до `assets/python/<revision>/` і `dist/assets/python/<revision>/`.
Ревізія пакета залежить від маніфесту; оновлення UI не вимагає повторного
завантаження незмінних Python-файлів.

## Як користуватися

1. Відкрийте «Теплообмін і гідравліка» → «Бібліотеки ht / fluids».
2. Підготуйте пакет (~32 МБ), дочекайтеся його окремої готовності.
3. Виберіть бібліотеку й завантажте каталог; знайдіть функцію, клас або дані.
   Документація показує upstream-сигнатуру, одиниці й опис обмежень.
4. Передайте аргументи через JSON і виконайте `call` або `get`.
   Кнопки Nu / f заповнюють готові приклади. Результат можна експортувати в JSON.

Це універсальна панель із JSON-аргументами. Окремі зручні форми для всіх функцій
ще не створено. Базові кореляції бібліотек не підміняють автоматично чинні
водяні, газові чи реакторні розрахунки.

Приклад ht, `call`:

```json
{"target":"ht.Nu_conv_internal","kwargs":{"Re":100000,"Pr":0.7}}
```

Приклад fluids, `call`:

```json
{"target":"fluids.friction_factor","kwargs":{"Re":100000,"eD":0.0001}}
```

Наявні також позиційні `args`. Векторні входи NumPy передаються як
`{"$array":[100000,200000]}`; комплексні — `{"$complex":[1,2]}`;
посилання на публічну функцію — `{"$function":"ht.Nu_conv_internal"}`.
Це фіксований міст даних, а не виконання Python-тексту користувача.

Класи повертають об'єкт із `handle` і публічними `members`:

```json
{"target":"fluids.geometry.TANK","kwargs":{"D":1,"L":2,"horizontal":false}}
```

Після конструктора, `get`:

```json
{"handle":"object-1","member":"V_total"}
```

Публічний метод об'єкта викликається через `call` з handle/member та args/kwargs.
Об'єкт як аргумент: `{"$object":"object-1"}`. `release` з handle звільняє посилання.
Handles живуть лише в поточному Worker: скасування, тайм-аут, перезавантаження
або видалення пакета їх анулюють. JSON-експорт зберігає входи та результати,
але не серіалізує внутрішній Python-об'єкт для відновлення між сеансами.

## Обсяг і числова достовірність

Каталог обходить публічні експорти кореня та безпосередніх підмодулів пакетів.
Він включає псевдоніми, тому кількість записів не дорівнює кількості унікальних
алгоритмів. Доступність імпорту не доводить працездатності кожного виклику.
Optional-розширення, які потребують Numba, Pint або інших відсутніх залежностей,
позначаються в `unavailableModules`. Довільне встановлення нових залежностей
під час виклику не виконується.

Параметри й результати використовують одиниці upstream, переважно SI, без
автоматичного перетворення одиниць наявного калькулятора. Метадані одиниць
витягуються з docstring і не є незалежно перевіреною схемою. Якщо одиницю
не встановлено, повертається null; вона не вважається безрозмірною.
Зберігаються точні JSON-числа без форматування; великі цілі, нескінченності та
комплексні результати мають окремі типізовані представлення. Максимальна
довжина вихідного масиву/послідовності — 100 000 елементів, вкладеність — 30.

У реєстрі обидві бібліотеки мають `numericalAcceptance: "pending"`, а відповіді —
попередження `integration-only`. Перевірка кількох контрольних викликів нижче
підтверджує інтеграцію. Повне незалежне числове приймання, домени застосування,
методи вибору кореляцій та спеціальні UI-форми — наступний етап.
Відповідність Steam97Web цим підключенням не встановлюється.

## Офлайн і життєвий цикл

Пакет готується окремо від основного кешу PWA. Кожний файл перевіряється за
розміром і SHA-256, completion marker записується останнім. Обрив, скасування
чи неправильний хеш видаляє частковий пакет. Web Locks координує підготовку
та видалення між вкладками; без цього API підготовка відхиляється явно.
Worker перевіряє повноту пакета перед кожним викликом. Service Worker віддає
ресурси з окремого кешу відповідної ревізії, включно з Pyodide .mjs та WASM.

Після підготовки працюють новий запуск браузера та новий Worker без мережі.
Повний ZIP уже містить усі файли; підготуйте пакет з локального serve.py до
зупинки сервера. Кнопка видалення прибирає лише кеш Python, зберігаючи проєкти.
Старі ревізії Python автоматично не прибираються; UI видаляє свою поточну ревізію.
Квота та довготривале збереження залежать від браузера. Фізичні Android/iOS
пристрої й дуже великі розрахунки в цьому етапі не перевірялися.

## Відтворювані перевірки

- `npm test`: контракт, прогрес, скасування, reset, повнота й цілісність пакета.
- `npm run test:python-libraries`: Chromium; для Firefox — змінна
  `BROWSER_NAME=firefox`. Обидва сценарії додано до `verify:release`.
- Браузерний сценарій: повний пакет; холодне скасування та повторний запуск;
  каталог і доступність UI під час старту; Nu і коефіцієнт тертя; JSON-експорт;
  клас TANK; NumPy-масив; екран 390 px; закриття профілю, відключений сервер і
  повторний офлайн-старт; втрата кешу; пошкоджений wheel і повторна підготовка.
- Докази запусків: `.release/python-libraries/<browser>/report.json`,
  `libraries.png`, `offline.png`. Точні підсумки завершеного запуску наведено
  в `PYTHON_LIBRARIES_ACCEPTANCE_UK.md`.
