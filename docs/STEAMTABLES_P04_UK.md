# P04 — дослідження контракту дисоціації

Стан на 19.10.2026: підготовку продовжено; реалізація числової поправки **заблокована даними**, повний спринт не прийнято. P03 запушено окремим комітом `c253b58` (1.35.11). Ця робота не змінює програму чи її версію.

## Що підтверджено

[Офіційна довідка](https://www.steamtablesonline.com/help.aspx) пов’язує модель із Bücker/Span/Wagner 2003 та задає верхню межу 2000 K, повне згоряння й **λ > 1,05**. Це необхідні умови, а не достатній критерій застосовності. Нижню межу саме дисоціаційної поправки довідка окремо не задає. Опис інтерфейсу містить вісім відсотків складу та прапорець, але не пояснює отримання λ.

Додатково знайдено [публікацію Roland Span 2004](https://www.researchgate.net/publication/228826657_Thermophysical_Properties_of_Aqueous_Systems_for_Analysis_and_Design_of_Power_Cycles_with_CO2_Capture), с.6, із прямою вказівкою: спрощена модель Bücker та співавторів не застосовна до oxyfuel-процесів. Посилання [17] веде саме на статтю 2003 року. Це обмеження моделі; числового порога N₂ чи правила відмови Steam97Web воно не встановлює.

[LibIdGasMix](https://f-m.hszg.de/fileadmin/Redakteure/Fakultaeten/Thermodynamik/Dateien/FluidVIEW_LibIdGasMix_Docu_Eng.pdf) використовує іншу поправку — VDI 4670. Її тиск, температурні пороги та нулі h/s не переносимо до нашого BSW2003. Повний перелік доказів і обмежень — [sources.json](steam97-p04/sources.json).

## Чому не можна автоматично вивести λ зі складу

Власна незалежна перевірка використовує точні раціональні числа й атомні баланси. Для явно заданого бінарного повітря 21 % O₂ / 79 % N₂ два процеси дають **ідентичні кількості всіх восьми продуктів**, але різні λ:

| На 1 моль палива | CH₄ | CH₃OH |
| --- | ---: | ---: |
| Стехіометрично потрібний O₂, моль | 2 | 1,5 |
| Поданий із повітрям O₂, моль | 2,08 | 1,58 |
| Додатковий інертний N₂, моль | 0 | 79/42 |
| λ | 1,04 | 79/75 ≈ 1,053333 |
| λ > 1,05 | ні | так |

В обох випадках продукти: CO₂ = 1 моль, H₂O = 2 моль, O₂ = 0,08 моль, N₂ = 4108/525 моль; Ar, CO, Ne, SO₂ = 0. Різницю азоту повітря компенсує інертний азот другого процесу. C/H/O/N балансуються точно; реакції описують повне згоряння **до врахування дисоціації**.

Формула `λ = (N₂·21/79) / (N₂·21/79 − O₂)` працює в цьому прикладі лише за додаткового припущення, що весь N₂ походить із зазначеного повітря. Для другого процесу вона дає неправильні 1,04. Це доказ неоднозначності загальної постановки, **не встановлення алгоритму чи дефекту Steam97Web**. Якщо його модель забороняє азотне розбавлення й обмежує палива, правило може бути однозначним у тих межах; такі припущення ще треба знайти.

Відтворення: `python3 scripts/reference/dissociation_input_audit.py`. Незалежний від коду програми розрахунок перевіряє баланс атомів, збіг усіх восьми молярних часток, різні боки межі λ та помилку азотного трасера. Результат — [input-identifiability.json](steam97-p04/input-identifiability.json). Це не тест числових властивостей дисоційованого газу й не контрольний результат оригіналу.

## Готові наступні задачі

Машиночитаний [контракт і задачі](steam97-p04/contract.json) відділяють підтверджені обмеження від невідомих. Потрібні первинні рівняння/коефіцієнти, припущення про паливо/окисник/розбавлення та λ, базис складу й нулі h/s, межі тиску, зміст «Dissociation», визначення cp/cv і off/on приклади оригіналу. Нульові h/s чистих компонентів P03 не містять ентальпій утворення: їх не можна безпосередньо використати для хімічної рівноваги.

Після отримання даних: окремий числовий еталон підтвердженої поправки → ядро й перевірки меж → Worker/скасування → форма/проєкт/експорт → обидва браузери й регресії P03. До цього не додаємо непідтверджену поправку чи числове значення «Dissociation».
