# Аудит користувацьких сценаріїв та дизайн робочої області — 1.24.0

Мета — полегшити користування наявними розрахунками. Аудит виконано у браузері на типових сценаріях та всіх 28 розділах каталогу.

## Послідовність роботи

Робочий шлях: **задача → введення → розрахунок → читання результату → історія / графік / звіт → збереження**. На кожному етапі потрібні поточні дані та одна зрозуміла головна дія. Налаштування, описи методів та журнал не повинні забирати більшість екрана до введення параметрів.

| Сценарій | Виявлена незручність | Зміна |
|---|---|---|
| Властивості за двома параметрами | Висока шапка, вузький блок вводу, повтор назви програми, вертикальна колонка кнопок | Компактна навігація, дві пари параметрів поруч на ПК, кнопки копіювання біля результату |
| Розрахунок турбіни / теплообмінника | Форму й результат потрібно прокручувати всередині невеликої панелі; частина дій дублюється | Послідовна сторінка; оригінальні CSV/графічні кнопки перенесені у спільну панель |
| Великі навчальні форми | Пояснення займають початок екрана, а поля обрізані висотою панелі | Пояснення розгортаються окремо; форма має природну висоту документа |
| Робота з історією | Постійна панель забирає висоту навіть під час введення | Журнал нижче результатів; явна дія переходить до нього |
| Одиниці | Панель налаштувань постійно забирає ширину | Панель за кнопкою, хрестик/Escape; локальні одиниці завжди біля поля |
| Звіт | Великий редактор обмежений внутрішньою прокруткою | Звичайна сторінка зі змістом і переходами, які додані в 1.23.0 |
| Телефон | Кілька вертикальних прокруток та дрібні кнопки | Одна прокрутка розрахунку, локальне прокручування широких таблиць, основні кнопки від 44 px |
| Побудований графік: ПК → телефон | Canvas зберігав ширину попереднього екрана до обробки resize | Максимальна ширина обмежена контейнером; перевіряються вже розраховані сценарії |
| Клавіатура | Пошук і переходи між керуваннями неочевидні | Ctrl/Cmd+K, перевірений Tab, Enter для розрахунку, Escape для панелі та повернення «До розділів» з довгих сторінок |

Вихідна перевірка 1366×768 показала внутрішнє обмеження висоти у 16 звичайних розділах. Вміст не втрачався, але потребував окремої прокрутки в панелі. Метадані та початкові знімки: `.release/ui-124/catalog-before.json`, `.release/ui-124/before-*.png`.

## Реалізація та збереження можливостей

Звичайні розрахункові сторінки використовують природну висоту документа. Власні робочі місця T–s/h–s/P–h з масштабуванням та розгортанням зберігаються. Таблиці, історія, відкриті налаштування та попередній перегляд документа мають локальні області прокручування там, де це потрібно.

Перевірка поля при переході на «Розрахувати» виконується в обробнику подання форми: повідомлення не зсуває кнопку між натисканням і відпусканням миші. Помилковий ввід установлює фокус у відповідне поле вже з першого натискання.

Спільна панель переносить оригінальні кнопки та їхні обробники. Перед перебудовою панелі та перед заміною HTML результату кнопки повертаються до їхніх позицій; якщо результат уже замінено, старі обробники видаляються разом зі старим результатом. Це перевіряється повторними розрахунками, перемиканням мови та CSV з різними числовими даними. Окремо усунено втрату обробника CSV після повторного рендерингу. Спеціальні додаткові дії, як P–h або передача виходу у загальні властивості, залишаються доступними.

Одиниці й фізичні значення, моделі, JSON-проєкти, звіти та алгоритми графіків не змінюються. Панель залишає поточну задачу доступною й закривається без підтвердження; зміни полів виконуються лише через відповідні елементи керування. Описи методів доступні при роботі, відкриваються перед друком і відновлюють свій попередній стан після нього. Підтвердження копіювання знаходиться біля результату.

## Перевірка

`npm run test:task-ui` проходить усі 28 розділів на 1366, 390 та 320 px — 84 компонування. Перевіряє сторінки після розрахунків циклів, АЕС, LMTD, лабораторних і курсових задач, а також відсутність горизонтального переповнення документа, вкладеної вертикальної прокрутки звичайних форм, клавіатуру, одиниці, повторні CSV, відсутність дублікатів основних кнопок, мову, друк пояснень та автономний файл.

`BROWSER_NAME=firefox npm run test:task-ui` повторює цей сценарій у Firefox. Повне приймання охоплює решту наявних сценаріїв, діаграми, звіти, PWA, числові звірки та ZIP. Фактичні результати записуються в `RELEASE_AUDIT_UK.md` і `RELEASE_ACCEPTANCE.json`.

Реакторна курсова залишається «У розробці». Нових фізичних моделей у цьому спринті немає.
